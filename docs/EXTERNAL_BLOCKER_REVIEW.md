# Gate 4E external blocker review

This review challenges the five Gate 4D external classifications. A missing
convenience API is not treated as a blocker when the same fact can be read from
documented chain contracts, events, or an official SDK.

| Feature                   | Previous reason                                    | Official sources checked                                                                                                                                                                                                                                     | Onchain alternative                                                                                                                   | SDK / public API alternative                                                                         | Final classification | Remaining limitation                                                                                                                                                                 |
| ------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Four.meme lifecycle       | No stable source or adapter in the repository      | Current Four.meme developer/onchain documentation and BNB factory references were checked during Gate 4E review; no sufficiently stable, versioned lifecycle contract/API was available for a reproducible reader                                            | Generic BNB factory/pool discovery remains available; it proves DEX activity but not Four.meme bonding/graduation semantics           | No verified public API/SDK was accepted as authoritative                                             | EXTERNAL_BLOCKED     | Four.meme-specific lifecycle is unavailable; BNB markets are still discovered through PancakeSwap/factory evidence and are never labeled Four.meme lifecycle states without evidence |
| Flaunch lifecycle         | Convenience endpoint was not previously integrated | [Flaunch REST data API](https://docs.flaunch.gg/references/restful-data-api) documents public token, new-token, price, history, and holder endpoints                                                                                                         | Base/Robinhood EVM factory and pool readers remain available independently                                                            | `FlaunchPublicApiReader` consumes the documented public API and validates response shape             | IMPLEMENTED          | Public API availability is monitored and unavailable responses remain explicit; API network coverage must not be inferred beyond documented networks                                 |
| Arc-native discovery      | No specialized launchpad API was known             | Arc EVM compatibility and network configuration are documented by [Arc](https://docs.arc.network/), while the repository uses generic factory/event readers                                                                                                  | Generic EVM bytecode, factory event, pool-state, and token reads are sufficient for verified Arc DEX deployments                      | Configured EVM venue reader; no vendor lock-in                                                       | IMPLEMENTED          | Venue addresses are configuration and must be supplied from current official deployment data                                                                                         |
| Robinhood venue discovery | No specialized venue adapter was present           | [Robinhood Chain EVM documentation](https://docs.robinhood.com/chain/deploy-smart-contracts/) and [connection documentation](https://docs.robinhood.com/chain/connecting/) establish the public EVM RPC and standard tooling                                 | Generic EVM factory/pool event and state reads provide token/DEX discovery                                                            | Flaunch public reader is supported only where its documented network API actually covers the network | IMPLEMENTED          | Public RPC rate limits and venue deployment configuration remain operational dependencies                                                                                            |
| Solana directional depth  | No supported venue account reader                  | [Raydium developer documentation](https://docs.raydium.io/), [Meteora developer documentation](https://docs.meteora.ag/developer-guide), and the documented Pump.fun bonding-curve lifecycle at [pump.fun](https://pump.fun/docs/bonding-curve) were checked | Venue-specific normalized pool state can be read from Solana RPC and quoted locally; unsupported account layouts return `UNAVAILABLE` | Raydium/Meteora SDK boundaries and canonical RPC remain optional transport implementations           | IMPLEMENTED          | Only supported pool generations are available; no TVL-derived depth is permitted and unsupported layouts fail closed                                                                 |

## Credentialed enrichment

Helius, GoPlus, and Bubblemaps remain optional enrichment providers. Missing
credentials do not block ordinary token/venue reads, but a risk tier that
requires a particular evidence class remains `WATCH`/`BLOCKED`; missing data is
never converted into a pass.
